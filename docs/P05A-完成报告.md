## 只读保证

```python
ALLOWED_SUBCOMMANDS = (("api",), ("pr", "view"), ("pr", "list"))
FORBIDDEN_FLAGS = ("-X", "--method", "-f", "--field", "--input", "-d",
                   "--raw-field", "--post", "--patch", "--put", "--delete")
```

- 只走 `gh api repos/{repo}/pulls/{n}` 的 GET。
- `assert_readonly(argv)` 在调用前拦截写参数。
- 单元测试**不做源码字符串匹配**（早期版本 `assertNotIn("--method", source)` 会命中常量定义本身），改为真实调用后断言 argv 恰为 `["api", "repos/.../pulls/1"]`。

## 三态状态来源

| `state_basis` | 含义 | 状态取值 |
| --- | --- | --- |
| `github_realtime` | 本次查询成功确认 | `draft`/`open` → `pr_created`；`merged` → `pr_merged`；`closed` → `pr_closed` |
| `github_realtime_stale` | 本次失败，沿用最后一次成功观测 | 同上，但注明最后成功时间 |
| `publish_log` / `receipt` | 无实时数据时的历史依据 | 历史结论 |

**防降级**：一次 401 不能把 `pr_merged` 打回 `pr_created` —— 失败时保留最后成功观测并标记 `stale`。

## 防旧覆盖

- `checked_at` 用 `timespec="microseconds"`（原来只到秒）。
- `_strictly_newer()` 严格大于比较：同秒内的第二次查询不再被 `skipped_stale` 丢弃，Draft→Merged 能生效。
- 回归用例覆盖：同秒两次查询、乱序写入、失败后旧结果回灌。

## 已知限制

- 实时查询依赖 `gh` CLI 与有效登录态；无网/401 时只能给 `stale`，不能给「现状」。
- `gh` Token 权限含 `repo`（大于只读所需），代码层用参数守卫补偿，但权限本身未收窄。
- 本阶段**不启用后台常驻**（那是 P05-B），不自动合并 PR。
